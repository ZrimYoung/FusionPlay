- 本机 Windows 11 x64、MSVC、.NET 10：共享 SDK 单元测试 106 项通过，真实音频端点测试默认跳过；Host 单元测试 12 项通过，真实网络测试默认跳过。Windows 界面构建无警告、无错误。
- 已单独运行默认真实音频端点的静音输出/暂停检查，通过；该检查也在同一输出流内修改 50 ms 补偿再归零，确认两次重新对齐，不重建端点。另有合成 PCM 测试验证校准跨过零增益后才重排时间线。上述检查不证明可听声音或跨设备同步。
- C# 核心和真实 DLL 交互验证 16 项通过，覆盖身份持久化、重复释放、独占锁、音量竞态、封面 HTTP/内嵌格式、取消和限额、便携数据归属及脱敏日志，以及端点补偿的跨重启持久化和错误端点隔离。
- 早期版本曾完成本机 LAN 连续三次启动/停止与错误控制报文隔离检查。手机实播期间不并行启动诊断接收器。
- 用户通过小米手机选择新身份 FusionPlay-Win-Test，确认连接成功、电脑有声音。随后反馈电脑相对同组音箱慢半拍；尚无同次录音量出的偏差。
- 原生播放窗口已在本机打开并观察。单独发布时发现缺失 WinUI 编译资源，已将完整运行目录复制到便携包；每次发布必须进一步检查 ZIP 解压后的启动。
- 本机设置窗口已验证固定“扬声器”可写入设置，并恢复到原系统输出作为比较基准；手动校准 +10 与归零均在界面和保存文件中核对成功。当前测试实例保留补偿 0，用户可自行调整。

## 本轮修正

自动网卡排序优先物理 Wi-Fi / Ethernet，避免隧道网卡抢先。Windows 专用控制端口优先 18899，避开常见的 8899 设备缓存/端口混淆；这并未证明此前连接问题只有这一个原因。

网卡与声音设备改为读取实际选中项。旧媒体会话关闭事件按代数隔离，避免覆盖新会话。声音同步校准与 Android 端一致，提供 −10 / +10 / 归零，也可输入具体数值；按真实声音端点保存，范围 0–500 ms，默认 0。调整时短暂淡出、重新对齐再淡入，保留现有手机连接；用户可边听边调。

## 尚待验收

- 同组音箱的真实声学偏差不超过 20 ms，且至少连续播放 30 分钟。
- 手机反向播放/暂停/前后曲、Windows 系统媒体卡片和硬件媒体键的端到端确认。
- 实播封面加载及错误恢复、音量拖动/滚轮/键盘与手机音量回传。
- 托盘隐藏/恢复/退出、睡眠唤醒、切换网卡和声音端点、多个音乐应用的媒体卡片共存。
- Windows 10 22H2 实机；Mac 与 Android 回归。已提供 CI 定义，但本轮未在对应平台运行，不记为通过。

## 声学测量方法

使用另一台录音设备采集同组音箱与电脑同时播放的清晰短音或鼓点，录音位置与两个发声点尽量等距，记录两者距离和电脑实际输出设备。保持妙播手机持续投放，避免在投放手机上启用会中断播放的录音功能。

手动调节不要求录音。需要严格验收时，先保留补偿为 0，测量多个瞬态信号的相对偏移，明确电脑是提前还是落后。若电脑落后，再按测得值增加该声音输出的提前补偿，并用同样方法复测。在开始、中段、30 分钟末段分别取样，记录最大偏差与变化；距离差的声传播时间也要计入。

软件的队列长度、WASAPI 预测输出延迟和调度误差用于定位问题，不能替代麦克风记录的最终发声时间。蓝牙输出不纳入首版 20 ms 验收。
