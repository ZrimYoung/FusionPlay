# FusionPlay Mac · 测试版

macOS 14+ / Apple Silicon。原生 SwiftUI 菜单栏界面，通过 UniFFI 调用共享 Rust MiPlay SDK，音频直接交给 macOS 输出。

## 使用

在独立项目根目录双击 `启动.command` 或打开应用，程序会读取已保存设置并自动启动接收服务。可随时点击“停止接收”；关闭或重新打开播放窗口不会重启已手动停止的服务，完整退出并重新打开应用则自动启动。不会添加登录启动项。手机连接同一局域网，关闭影响本地通信的代理，在妙播中选择 `FusionPlay-Mac`。全屋播放由手机组织，将 Mac 与音箱一起加入即可。

首次出现局域网权限提示时允许访问。在“设置”中可以选择网卡和输出设备；默认自动选择局域网、跟随系统音频输出。修改设置后需要重新连接，手机可能需要重新选择设备。

关闭设置窗口不会停止接收。“停止接收”释放接收器；“退出”或 `停止.command` 关闭应用。不安装登录启动项，不修改全局 Python、Rust 或 shell 配置。

打开应用时显示独立播放窗口；点击程序坞图标可再次打开。菜单栏面板的“正在播放”也可打开该窗口，显示封面、歌名、歌手、音量与手机提供的进度。背景使用当前封面模糊铺满，无封面时显示安静渐变；播放按钮在支持的系统上使用原生玻璃效果，旧系统使用半透明材质，减少透明度设置下使用实色。播放页不显示底部状态栏或接收启停按钮；接收启停保留在菜单栏。关闭播放窗口也继续接收。菜单栏与播放窗口都提供上一曲、播放/暂停、下一曲。

实际播放后，应用通过 macOS MediaPlayer 接入控制中心/系统菜单栏的“正在播放”及键盘媒体键。系统菜单栏是否展示“正在播放”取决于系统设置；多个音乐应用同时运行时，由 macOS 决定媒体键的控制目标。停止接收、断开会话、睡眠或退出时清除本应用媒体信息。

控制操作发送给手机播放源。界面区分“指令已发送”和“手机已确认”；未确认不自动重发，以免重复切歌。全屋播放时对整组的影响由手机决定，需要实播验证。仅连接或握手不会占用系统“正在播放”。

封面支持手机提供的 HTTP/HTTPS 图片地址、`data:image/...;base64,...` 内嵌图片及无前缀 Base64 图片，最多 4 MB，使用临时内存加载，不写图片磁盘缓存。网络超时或服务端临时错误最多尝试三次；设置中的“专辑封面”区分手机未提供、正在加载和加载失败，并可手动重新加载。时长/位置缺失时不伪造进度；应用内支持点击和拖动跳转。系统媒体进度跳转仅在有有效曲目、时长和位置时启用，实际入口由 macOS 提供；不向系统注册连续快进/快退。

为兼容手机提供的 HTTP 封面，本应用设置了自身的 ATS 例外；不修改系统设置。URLSession 只用于封面 GET，不携带 Cookie 或已存凭证，不接受文件路径、带用户名密码的 URL 或其他协议；HTTPS 仍执行系统证书验证。

0.3.0 起安装在 `/Applications/FusionPlay Mac.app`，运行数据位于 `~/Library/Application Support/FusionPlay`，不依赖外置盘。旧版首次迁移可运行 `python3 macos/scripts/install-local.py`，复制并校验配置、身份，拒绝覆盖已有安装。源码与构建缓存留在项目目录。

## 构建与验证

需要 Rust stable（支持 edition 2024）、Apple Command Line Tools（Swift 6 工具链）和网络访问。Swift 源码以 Swift 5 语言模式编译，以兼容 UniFFI 0.29.4；UI 使用 macOS 14 API。

```sh
bash macos/scripts/build.sh
bash macos/scripts/install-entries.sh
bash macos/scripts/test-bridge.sh
bash macos/scripts/test-artwork.sh
# 在有可用局域网且未运行本应用时：
bash macos/scripts/test-bridge.sh --network
# 原生 MediaPlayer 发布/暂停/清理检查（短暂使用测试曲目，结束后清除）：
bash macos/scripts/test-bridge.sh --network --system-media
python3 -m unittest discover -s macos/Tests
```

`env.sh` 优先使用相邻 Android 项目已有的工具链，依赖缓存和构建产物均写入本项目。其他机器使用 PATH 中的 Rust；可通过 `FUSIONPLAY_PROJECT_ROOT` 指定独立产物根目录。应用使用本地 ad-hoc 签名，没有 Developer ID 公证。

Rust 测试：在 bash 中加载 `macos/scripts/env.sh`，然后分别对 `src/FusionPlay.MiPlaySdk/Cargo.toml` 和 `src/FusionPlay.Host/Cargo.toml` 执行 `cargo test --locked --manifest-path …`。部分测试会绑定本地套接字，需要允许本地网络操作。

## 架构与分支兼容

- `src/FusionPlay.MiPlaySdk`：唯一共享协议核心。Mac 音频回调使用固定容量 SPSC 缓冲，保留每帧时间戳；小偏差平滑调速，严重失步先淡出再重新同步。
- `src/FusionPlay.Host`：新增类型化宿主契约与 UniFFI 适配。Swift 接收状态快照，不解析 SDK 内部 JSON。事件线程处理日志和 UI 订阅，音频线程不调用 Swift。
- `macos`：原生 UI、打包及清理入口。Android Flutter/Kotlin/JNI 保留原实现。

平台修复以 `target_os = "macos"` 隔离。共享 Lyra 生命周期修复单独提交，供 Android 分支独立合入。基线与分支见 `BASELINE.md`。不复制核心、不重命名现有 Android 工程、不修改其包名或校准值。

## 诊断及实播验收

日志在项目 `logs/receiver.jsonl`，单文件约 5 MB 轮换一次，只保留当前与上一份。记录缓冲量、输出延迟、调度误差、欠载、丢帧和重新同步计数；不保存认证材料、原始包、封面或曲目信息。设备身份和设置在 `data`，目录权限 700，文件 600。

封面诊断另存 `logs/artwork.jsonl`，约 50 KB 轮换，只记录来源格式（HTTP/HTTPS/内嵌/无前缀编码/手机地址/缺失）、结果代码和尝试次数，不记录 URL、查询参数、歌曲名或图片内容。

先以 Mac 内置扬声器验证：发现、连接、播放/暂停、重连、加入/退出全屋，然后连续播放至少 30 分钟。观察是否有毛刺、断音或随时间扩大的偏差。启动对齐产生的丢帧与持续播放期间的异常需要分别判断。

20 ms 是工程目标，必须用同一录音中的瞬态信号测量；菜单栏“调度误差”不等于声学同步偏差。只取得听感反馈时标记“主观通过，客观偏差未测”。蓝牙音频设备不属于首版同步验收对象。

网络或输出设备变化会触发受控重连；失败最多自动重试三次。睡眠时停止，唤醒后恢复用户此前请求的接收状态。手机可能需要重新选择设备。实际睡眠、网络切换及输出切换仍需逐项实测记录。

实播中断或未完成不能宣称毛刺已修复。详见 `VALIDATION.md`。

系统媒体验收：手机投送后，检查控制中心曲目和封面，再分别使用键盘、系统卡片、菜单栏、独立窗口操作播放/暂停和切歌；确认手机实际变化、暂停后没有误显示播放、断开后卡片消失。与其他音乐应用切换时检查媒体键归属。原生接口测试通过不等于以上实播已通过。

## 清理

设置中的“打开数据与卸载目录”可找到 `卸载 FusionPlay.command`。查看清单并输入 `DELETE` 后，会退出应用并删除内置盘应用、本应用运行数据、偏好、窗口状态和专用缓存。外置盘源码、构建产物、缓存以及迁移前备份保留；系统隐私授权记录不承诺清除。

迁移前外置盘 `data` 和 `logs` 保留为备份，不再作为当前运行目录。原 `macos/scripts/cleanup.py` 仍是外置盘开发产物清理工具，与安装版卸载分开。

项目继承 AGPL-3.0-only 许可证；分发应用时应同时提供对应源码与许可证。

应用图标位于 `macos/Resources/AppIcon.png`，采用浅底蓝色双环与轻微玻璃质感；提示词和生成方式见同目录 `AppIcon.prompt.json`。构建自动生成多分辨率 ICNS，不需要额外图像工具依赖。

菜单栏使用单色双环标志：默认双环，播放与暂停改用居中的单环，环内分别显示三角和双竖线；单环直径与双环中的每个环一致，菜单栏占位尺寸不变。菜单顶部为封面、歌曲信息与播放控制；点击封面或歌曲信息打开正方形迷你播放器。歌曲信息下方显示手机上报的播放进度，菜单进度条支持点击或拖动跳转：松手后发送到手机，并根据手机回报确认。无有效时长、未连接或拖动期间曲目变化时不会发送跳转。底部左侧为设置和音量按钮，点击音量按钮后横向展开可点击、拖动的细线音量条，再次点击收起；右侧为退出。音量仍支持辅助功能调整。接收启停与日志位于设置中。

运行时显式设置 Dock 图标，使用带透明外边距的圆角图块，图块内部保持不透明。图标回归检查：`bash macos/scripts/test-brand.sh`。

控制连接的局部错误会记录到诊断日志而不会重启整个接收器；日志使用 `scope`、`recovery` 和固定 `reason_hint` 分类，不保存原始错误内容。真正的音频输出或监听故障仍走接收器恢复流程。

菜单和播放窗口共享音量拖动状态，拖动/提交期间忽略旧音量回报，命令完成并收到对应回报后恢复跟随手机。回报丢失时最多等待两秒，避免永久锁住滑条。回归测试：`bash macos/scripts/test-volume.sh`。

### 0.2.6 设备发现与恢复

Mac 安装保存自己的控制端口，避免默认复用电视常见的 8899。首次升级保留设备身份并迁移配置；端口被占用时保存实际分配的替代端口。此措施降低旧地址误连其他设备的风险，不能清除手机上已有的错误记录，升级后手机可能需要重新选择设备。

### 可缩放播放窗口

拖动窗口边缘可缩放，最小内容尺寸为 260 × 260。宽度不足 600 或高度不足 360 时采用封面迷你模式，保持 1:1 缩放，鼠标移入显示曲目信息和上一曲、播放/暂停、下一曲，移出后隐藏。VoiceOver 启用时保留控件；普通模式仅悬浮显示，移出隐藏。放大后自动恢复左右布局；无封面显示音符占位。窗口背景支持拖动，关闭窗口继续接收。

迷你悬浮层右上角可选显示图钉，用于切换窗口置顶；置顶与按钮显示均在外观设置中保存，默认关闭。模糊背景根据控件实际高度延伸至约 1.35 倍范围，模糊半径逐步增加到 40 点，随歌名换行和窗口大小变化。


### 设置与同步微调

设置使用可缩放的原生侧栏，分为接收、外观、高级、关于四页；默认 820 × 620，最小 660 × 500，内容可滚动。外观页可切换简体中文/English，并控制播放窗口是否显示上一首、播放/暂停和下一首（默认显示）；隐藏时收起对应高度，保留进度条，按系统减少动态效果偏好显示动画。

高级页直接提供 −200～+200 ms 同步微调：负值提前、正值延后，默认 0，松开滑块后保存并应用。恢复默认回到 0。调整经过短暂淡出和重新对齐；提前受已到达音频和最低安全缓冲限制，不能消除发送端/网络延迟。没有可用时间戳时的提前效果还受最低预缓冲限制。该偏好对本 Mac 的输出统一生效；诊断信息默认折叠，缓冲容量保持自动。

同步偏好保存在运行目录 `data/macos-sync.json`，UI 偏好保存在应用自己的 macOS preferences 域中；现有卸载入口会一并清理。设备身份与其他平台设置不变。关于页提供版本、项目主页和许可证信息。

验证语言切换及真实 Swift/Rust 同步设置读写：先构建，再运行 `bash macos/scripts/test-settings.sh`。测试使用独立临时目录，不修改当前接收器配置。

外观页还提供控件常驻、窗口置顶和显示置顶按钮，三项均默认关闭并自动保存。置顶设置与右上角按钮使用同一偏好；隐藏按钮不取消已开启的置顶。非驻留模式下，鼠标移出后停留约 0.4 秒，再用 0.65 秒淡出；移回会取消待执行的隐藏。系统“减少动态效果”开启时取消淡入淡出动画。

同步微调还支持输入整数毫秒值（回车或离开输入框时确认），以及滑块两侧的 − / + 按钮，每次调整 10 ms，边界为 −200～+200 ms。滑块不显示密集刻度，拖动结束后按整数毫秒保存。关于页双环使用 SwiftUI 矢量路径绘制，不再放大 Dock 位图。

外观页的“应用入口”可分别控制 Dock 图标和菜单栏双环图标，两项默认显示并自动保存。两者都隐藏后，再次打开应用会进入设置；以该偏好冷启动时也显示设置，以便恢复入口。隐藏图标不会停止接收。

菜单音量条在按钮右侧原位向右展开，裁切隐藏部分，不从左侧图标上滑过。菜单右下角退出按钮需要二次确认；取消不停止接收，确认退出后才关闭应用。


### 0.3.1 播放器与动画优化

基于主线 `720571df6a3a315a86a27937cfac15a0c26e175f`，包含共享核心的同曲跳转确认、暂停跳转与晚到回报保护。

菜单、大播放器与迷你播放器共用点击/拖动跳转。拖动中显示预览，松手后一次发送；界面暂留目标位置，以较淡的进度区分等待回报，手机实际回报后校准，失败或 5 秒未确认则回退。切歌、断开、时长变化和隐藏进度会取消过时手势。该预览不写入接收器状态或系统媒体信息。

外观页新增“显示进度与时间”（默认开启）及白色 / 跟随系统 / 自定义进度颜色，默认保留原白色。显隐用于大小播放器，收起时同步减少高度和渐变背景范围；菜单保留其进度入口。自定义色用于三处进度，菜单默认中性色保持主题对比度。

迷你悬浮动效分层：背景约 0.42 秒淡入，文字延迟约 0.1 秒开始、约 0.36 秒完成；移出保持 0.4 秒停留，文字约 0.42 秒淡出，背景稍后以约 0.65 秒退出。交互中保留控件显示，快速移回可反向过渡。播放按钮与进度区域以约 0.25 秒淡化、收放高度并裁切，不采用滑入；大小布局切换只做短淡换。系统“减少动态效果”关闭这些动画。

封面与模糊背景在一次 SwiftUI 动画事务中替换，共用约 0.35 秒过渡；继续保留旧封面等待新图，原生过渡处理连续切换，取消的下载不覆盖新图。菜单封面随右侧内容在 72～96 点内调整，副标题使用“歌手 - 专辑”。

检查：`bash macos/scripts/test-timeline.sh` 验证待确认进度和回退；`bash macos/scripts/test-ui-refinement.sh` 在隔离进程中检查中英文、四类设置及窗口大小并输出预览到 `artifacts/ui-refinement-check/`。透明后台的位图截图不能完整呈现系统材质、侧栏振动效果和实时动画，原生侧栏另核对实际行数。测试不会启动第二个接收器或更改用户偏好。


### 0.3.2 歌词显示

“设置 → 外观 → 播放显示 → 显示歌词”支持“自动 / 始终开启 / 始终关闭”。新安装默认为自动；旧版开关保留原选择，开启迁移为始终开启，关闭迁移为始终关闭。自动模式仅在收到有效歌词后显示，解析新的歌词期间保留布局，前奏、间奏和暂停不隐藏；无歌词或投送结束后关闭歌词区。始终开启时无歌词显示“暂无歌词”，始终关闭时不显示歌词区。封面迷你模式保持 1:1 和可缩放，歌词模式使用封面渐变模糊背景，当前句突出、前后句淡化，有翻译时合并在同一行下方。播放控件仍遵循悬浮/常驻及显隐设置；大窗口使用左侧封面与控制、右侧歌词布局。

接收手机 `SetMediaInfo.mLrc` 的 Base64 UTF-8 歌词，支持带时间戳的 LRC 和纯文本；时间戳歌词跟随手机回报与跳转预览自动居中，点击某句可请求手机跳转。手动滚动暂缓跟随 6 秒，也可点击“回到当前歌词”。VoiceOver 阅读时不因播放进度强制滚动；减少动态效果时取消滚动和淡化动画。

歌词由手机/音乐 App 提供，未发送时显示“暂无歌词”，不联网搜词。原文、翻译和时间戳仅在内存中使用，不写歌曲歌词日志或缓存；同曲的空增量更新保留歌词，切歌或媒体会话结束清空，后台解析结果不会覆盖新曲。输入最多 256 KiB，显示最多 4000 行；本版按句高亮，不实现逐字卡拉 OK。

检查：`bash macos/scripts/test-lyrics.sh` 使用合成文本验证时间戳、偏移、翻译、查找及输入边界；`test-ui-refinement.sh` 增加中英、最小/迷你/大窗口及无歌词、纯文本状态。真实手机播放、点击歌词跳转和滚动观感需要实播确认。


### 0.3.3 歌词布局与稳定性修正

歌词开启时，小窗口改为上方封面、下方歌词，可自由拉高或缩放；中间的细分隔条可拖动，比例自动保存。歌曲与控制仍叠在封面下缘，遵循悬浮/常驻设置；控件显隐不再改变歌词区域高度。仅关闭歌词的封面迷你模式保持 1:1。大窗口以宽度切换左右布局，可以独立调整宽高；播放、暂停、停止投送均不改变可缩放策略。

部分手机系统音乐会用当前歌词句更新标题。本版使用稳定曲目 ID 或 LRC 标题/文档指纹识别同曲，精确匹配歌词句的标题恢复为 LRC 曲目信息，不再反复清空歌词。缺少进度回报时保留最后的歌词位置；手机明确回报 0 时仍允许回到开头。跳转暂时禁用时保留歌词行视图身份。

新增 `test-window-behavior.sh` 和 `test-lyrics-follow.sh`，验证原生窗口比例释放、歌词竖向展开、宽而矮的大窗口、重复迷你请求、停止状态约束恢复，以及空进度、明确零值、断连和曲目切换。手机实播仍需复核连续滚动、拖动分区及停止投送后的窗口拖动。

设置页移除系统自动侧栏工具栏项，使用左侧固定侧栏图标展开/折叠，也可按 ⌃⌘S，避免自动项在展开过渡时出现空圆占位。


### 0.3.4 方形封面与设置操作栏

歌词迷你模式的上半部（封面及悬浮控制）始终为“窗口宽度 × 窗口宽度”。增加窗口高度只增加下方歌词区域；横向缩放时封面等比例变化，整个窗口不锁定长宽比。最少为下方歌词预留 128 点，另有 8 点分隔；移除此前的分区拖动。关闭歌词时仍是原来的方形封面模式。

设置页使用原生水平分栏和侧栏列表，移除自动生成侧栏工具栏项的导航结构，只保留一个显式侧栏按钮。接收页将保存/重新连接及停止接收固定到页面底部，状态和说明继续在表单中显示。

歌词当前句的阅读位置移至视口约上三分之一。上下边缘的歌词按所在位置逐渐增加模糊并淡出，中央清晰，不额外加深暗色遮罩；减少透明度或增强对比度时关闭边缘模糊。纯文本歌词保留自然滚动起点，首尾预留清晰阅读空间。

侧栏回归检查：`bash macos/scripts/test-settings-toolbar.sh`，使用独立原生设置窗口，检查连续开合及动画过程中的实际工具栏按钮数量，不启动接收器或修改用户设置。


### 0.3.5 歌词边缘与侧栏动效

歌词上缘使用较轻模糊并延长至约 30% 阅读区，下缘保留原强度、延长至约 45%；中央与当前句保持清晰。滚动内容左右增加模糊绘制留白，避免靠左文字被裁成直边，文字缩进和换行宽度保持不变。

设置侧栏内容固定宽度 172 点，只对外层 173→0 的裁剪宽度做约 0.22 秒收放；列表不移除重建，表单与工具栏不跟随隐式动画。标题使用独立居中项，窗口菜单仍保留原窗口标题。

封面诊断实收样本为 300×300 WebP、12974 字节，Mac 解码后仍为 300×300；该样本未触发接收端 800px 限制，放大清晰度主要受发送侧分辨率限制。不同音乐源仍可能不同；本轮未改变封面解码策略。


### 0.3.6 普通设置标题

macOS 26 的设置页标题显式隐藏系统共享玻璃背景，保留居中的普通文字。macOS 14/15 保持原有无玻璃标题路径。工具栏回归检查增加标题无边框断言，并通过 ScreenCaptureKit 仅捕获测试进程自己的原生窗口，核对侧栏展开/收起两种真实外观；不请求录屏授权，不捕获其他应用。


### 设置导航的两种布局

点击设置窗口左上角的侧栏按钮（或按 ⌃⌘S），可在左侧导航和顶部四页导航之间切换。顶部使用 macOS 原生分段选择控件，仍可直接进入接收、外观、高级和关于；当前页面与未保存的接收配置保持不变，导航布局自动保存。侧栏模式保留普通文字标题，顶部模式不重复显示页面标题。


### 0.3.8 歌词显示模式、留白与全屏

歌词显示改为自动/始终开启/始终关闭：自动按解析后的有效歌词显示，异步替换文档期间维持原布局，纯时间戳或元数据不触发展开。旧版显式开启/关闭分别迁移为始终开启/始终关闭，新安装默认自动。无歌词时始终开启仍保留空状态。

大窗口横向留白按窗口宽度在 36–48 点间调整。播放器支持原生绿色按钮及“显示 → 切换全屏”（⌃⌘F）；全屏期间暂停迷你窗口比例和尺寸规范，退出后恢复窗口布局与置顶偏好。隐藏 Dock 时也显式作为全屏主窗口。

`test-lyrics-display-mode.sh` 验证偏好迁移与自动显示，`test-ui-refinement.sh` 包含真实模型后台解析、延迟歌词与切歌、无歌词及大窗留白；窗口与工具栏脚本分别检查全屏生命周期和菜单快捷键。


### 0.3.9 界面细化

大播放器两侧留白按窗口宽度渐增到 52–80 点，600 点布局边界保持原最小留白；小封面模式与纵向歌词小窗保持原布局。手动浏览歌词后，停止滚动约 5 秒自动平滑回到届时的当前句，不再显示回位按钮；持续拖动和惯性滚动期间不抢回。VoiceOver 保持自己的阅读位置。

设置侧栏的原生半透明材质延伸到窗口按钮所在区域。展开/收起时先淡出标题或页签，再协调侧栏与内容区宽度，目标工具栏完成原生布局后淡入；快速反向采用最新目标，减少动态效果时直接切换。外观页参考 Windows 的短标签，以原生紧凑菜单选择歌词、进度颜色、控件显示方式及语言，原有设置键与默认值保持一致。


### 0.3.10 字体与播放器过渡

“设置 → 外观 → 字体”默认收起，摘要显示已选字族和字重。可搜索此 Mac 已安装的字体、选择该字族可用的字重，并即时预览及恢复默认。默认跟随系统字体、常规字重；更换字族时取最接近的可用字重。缺少已保存的字体时保留选择并回退到系统字体，不下载字体。字体用于界面、播放器、歌词和时间文字，保留原字号及强调层级，系统图标不跟随替换。偏好沿用应用的 UserDefaults，现有卸载入口会一并清理。

大窗封面与歌词间距从 32 点渐增到 48 点，最窄布局保留阅读宽度。歌词显隐不替换同曲的滚动视图，通过布局收放和淡化过渡；封面和详情在同一视图中调整位置。进度填充与背景共用轨道边界，随显隐布局一起变化，播放进度及跳转回退仍直接响应。减少动态效果时取消这些布局动画。

字体检查：`bash macos/scripts/test-typography.sh`。界面回归继续使用 `test-ui-refinement.sh` 与 `test-settings-toolbar.sh`；均使用隔离测试进程，不启动另一个接收器。


### 0.3.11 切歌窗口稳定性与标题修正

修复自动歌词模式下，新曲首帧没有歌词会先把小窗变成方形、歌词晚到后又使用默认高度的问题。新曲清除旧歌词正文后最多等待 2 秒元数据，重复空帧不延长等待；确认无歌词才自动收起。窗口记住用户手动调整的歌词区域高度，再次出现歌词时恢复。

播放器根最小尺寸固定为 260×260，不再由测得宽度反写根最小高度；原生窗口不再发布另一套动态 contentMinSize。小窗仍保持方形封面，手动缩放结束后只在必要时补足下方 128 点歌词与 8 点分隔。设置窗口的尺寸策略不变。

“设置 → 外观 → 修正歌词标题”默认关闭。开启后，仅在收到的 LRC 头信息或可核对的组合字段提供可信来源，且原标题匹配完整歌词或足够长的连续片段时恢复真实歌名。含连字符的名称按完整字段核对，无法确认时保持原样。应用与系统媒体显示使用修正结果，暂停时切换选项也刷新系统媒体；原 Snapshot、曲目 ID、播放/跳转请求保持不变。不联网搜歌，不保存歌词或新增歌曲正文日志；显示缓存只保留一项并随媒体会话清理。没有可核对元数据的歌曲不承诺恢复。

`test-player-lifecycle.sh all` 使用独立真实 Window Scene 检查切歌和歌词晚到；设 `FUSIONPLAY_LIFECYCLE_STRESS_SECONDS=75` 可追加合成封面与切歌压力检查，默认不运行加长模式。`test-display-metadata.sh` 验证标题规则；`test-ui-refinement.sh` 验证真实预览模型的晚到、超时与取消。检查不启动接收器或操作手机。


### 0.3.12 播放器空状态与侧栏图标

无当前歌曲时，播放器只保留原生透明毛玻璃、占位音符与系统窗口按钮，不显示标题、歌手、专辑、进度和播放控件。开始接收歌曲后继续按原来的显示偏好呈现；有歌曲但没有歌词或封面仍使用正常播放布局。毛玻璃使用 behindWindow 的系统 HUD 材质，减少透明度时跟随系统纯色回退，不改变窗口缩放策略。

设置侧栏继续采用苹果 SF Symbols，接收、外观、高级、关于分别使用扬声器、明暗圆形、齿轮和信息圆圈，并统一为较小的图标尺寸和常规字重。


### 0.3.13 菜单背景样式

“设置 → 外观 → 菜单面板 → 背景样式”可选择毛玻璃或液态玻璃并自动保存。新版系统与构建默认保留现有系统液态菜单外观；毛玻璃使用传统系统 popover 材质作为内容背景，菜单外框、阴影、定位及关闭规则仍由系统管理。仅改变菜单面板，不重启接收服务；播放器空状态的样式独立。旧系统回退毛玻璃，减少透明度时跟随系统设置。

### 0.3.14 清透液态玻璃菜单

“菜单面板 → 背景样式”的液态选项现为“清透液态玻璃”，由透明原生面板中的单个 NSGlassEffectView.clear 承载。移除原系统 MenuBarExtra 的厚背景，未添加染色或加深遮罩；传统毛玻璃仍可独立选择。旧系统或减少透明度时使用传统材质。切换材质复用同一个控件宿主，保留菜单操作状态，不重启接收器。

菜单由公开 AppKit 接口管理，支持点击外部、Escape、切换应用关闭，以及退出确认、入口显隐和位置记忆。设置与播放器窗口均可恢复菜单入口。原生检查脚本为 macos/scripts/test-menu-panel.sh；测试不启动接收服务、不写正式用户设置。

### 0.3.15 封面与歌词的分界

移除小窗口封面下方额外绘制的淡色分隔线。保留 8pt 透明间隔，不改变方形封面、歌词区高度或窗口缩放策略。

### 0.3.16 歌词换行过渡

横向缩放时，停止逐帧强制重新定位当前歌词。原生实时缩放期间保留阅读位置，结束后合并成一次平滑跟随；程序化连续宽度变化使用180ms安静期合并。手动浏览、拖动或旁白期间不抢占滚动位置。

原文和翻译仅在实际换行范围改变时使用约0.22秒的交叉淡变与行高过渡。保持同一实时Text、歌词行、点击跳转按钮与滚动视图，旧排版最多保留一张有界过渡图，减少动态效果时立即完成布局。`test-lyrics-reflow.sh`验证同宿主宽度序列、换行范围、辅助功能与跟随次数；不启动接收器、不修改正式设置。

### 0.3.17 系统全屏

播放器在 macOS15及以上明确启用 SwiftUI 原生全屏，避免自动内容尺寸推断把窗口改回 fullScreenNone。绿色按钮和 Control＋Command＋F 继续使用系统原生动作。macOS14保留原有 AppKit 策略。`test-fullscreen-eligibility.sh` 使用隐藏窗口覆盖自动推断与显式启用的差异，不进入全屏桌面。

### 0.3.18 全屏歌词比例布局

歌词双列以居中的阅读内容区布局：大窗口的左右留白随宽度增长至约10%，封面列从普通窗口约44%连续过渡至大窗口38%（均相对扣除列间距后的内容宽度）；列间距随内容区增长，超宽窗口限制阅读内容区最大1440pt并居中。封面随专辑列增大，同时受可用高度限制；矮窗口封面与文字、进度统一左对齐。

普通窗口保留已有最小留白，不缩小旧边距；无歌词横排与迷你播放器保留原方案。几何计算只作用于内容，不改原生最小尺寸、窗口比例或音频。`test-expanded-lyrics-layout.sh` 不打开窗口即可检查几何连续性与高度预算；界面预览补充1710×1112和2560×1440尺寸。

### 0.3.19 iPad 动效适配与设置详情

参考同仓库 iPad 原生实现：macOS15及以上用 TextRenderer 按真实字形位置做换行过渡，文字在跨行时模糊淡出、移动后淡入，同行文字滑动、行高分阶段变化；连续反向缩放从当前呈现状态继续。保留自定义字体与系统减少动态效果、旁白行为；macOS14使用有界 Core Text 字词渲染回退。歌词跟随等待最后一轮排版动效完成，再用420ms回到32%阅读位置；面板显隐为360ms淡化与12pt纵向位移。

字体与同步诊断改为点击打开原生详情面板，设置主页只显示摘要入口。字体选择、预览、恢复默认与诊断实时数据保留。设置顶栏使用渐变遮罩的原生模糊层，减少透明度时回退纯色。

菜单背景分为“磨砂玻璃 / 液态玻璃（默认）/ 液态玻璃（通透）”。新默认使用原生 regular，旧显式 liquid 选择仍映射通透 clear；两种玻璃不再叠加窗口阴影。旧系统回退磨砂玻璃，不重启接收服务。

### 0.3.20 可调歌词时差与内容顶部模糊

“设置 → 外观 → 歌词动效”新增交错滚动开关与时间跨度，默认开启140ms，范围0–240ms、步进10ms。此设置同时作用于自动跟随的逐行错峰滚动，以及横向换行时的逐行出现延迟；关闭或设0时同步运动。手动浏览、原生缩放、曲目切换与辅助功能会取消滚动波形，结束后停止刷新；调整不改变音频同步时间。

设置顶部模糊限定于右侧正文，侧栏、标题与系统窗口按钮不参与遮罩。滚动到内容顶边时渐变显现，返回顶部隐藏；使用活动状态的原生窗口内模糊与羽化蒙版，减少透明度时回退纯色。

### 0.3.21 歌词阅读调节

外观页的歌词字号可调75%–200%（默认100%，5%步进），主文与翻译按各自原字号同比缩放。单行移动时长可调100–1500ms（默认420ms，10ms步进）；交错时差上限扩至1000ms，默认仍为140ms。新增设置即时保存，不改变音频同步。长时差下连续推进从当前位移接续，使用33个有界采样而非旧动画递归链。

设置正文顶部改为直接对原生Form使用56pt可变半径模糊，最大24pt，不绘制额外材质或色层。按原生clip.visibleRect计算真正可见的正文顶边；正文明确裁到原生标题栏以下，标题与侧栏保持清晰。滚动位置为0、减少透明度或离开页面时移除自己的滤镜，并保留原有其他滤镜。


### 0.3.23 iPad 播放交互与共享歌曲识别

共享接收层结合手机提供的歌曲标识、歌词和播放位置区分字幕更新与真实切歌，并保留同一手机伴随控制连接中的曲目信息。原始标题继续用于控制与跳转校验；“修正歌词标题”开关只决定是否显示恢复后的曲目信息。系统媒体进度跳转也校验操作发出时的曲目，切歌后不会把旧请求应用到新歌。

外观设置新增“允许歌曲信息换行”和“歌词快捷按钮”。歌词按钮仅临时切换当前歌曲的显示状态，不改动“自动 / 始终开启 / 始终关闭”的保存设置；切歌、断开或修改显示模式后恢复按设置决定。

“窄窗布局”提供三种选择，均不显示页签：原有布局保留封面在上、歌词在下，关闭歌词时为方形封面；方形分页使用原来的封面与悬浮控件，在播放页和歌词页之间左右滑动，整个小窗口始终保持 1:1；独立播放页使用方形封面、歌曲信息、进度与播放控制，底部显示一行当前歌词，窗口宽高可自由调整。后两种均支持左右滑动，独立播放页也可点击当前歌词进入歌词页、点击歌词页的小封面或歌曲信息返回播放页。歌词页的小封面和歌曲信息可分别显示或隐藏。新安装默认原有布局；旧版已开启分页时迁移为方形分页。全屏期间释放小窗口比例；无歌曲时仍只显示毛玻璃和音符。

以上选项沿用已有设置和设备身份，不增加启动接收开关。

本轮定向检查：`test-metadata-pipeline.sh` 验证合成手机消息从协议解析到 Host 的原始/显示字段分离；`test-display-metadata-snapshot.sh` 检查 Swift 快照消费；`test-player-presentation.sh` 检查歌词临时显示策略、分页手势和原生组件；`test-player-narrow-ui.sh` 使用隔离的真实播放器窗口检查分页按钮、歌词摘要和最小尺寸。原生窗口分页、全屏及停播后的尺寸保持由 `test-window-behavior.sh` 和 `test-player-lifecycle.sh` 覆盖。

歌词缩放优化保留逐词模糊、行高与交错时序：不因容器宽度单独变化重复启动重排，生产构建不运行测试阶段采样，并对同一原生 run 内绘制状态完全相同的连续字形批量绘制。`test-lyrics-resize-performance.sh` 提供隔离的连续缩放检查；本机两轮交替对照中，完整 expanded/compact 歌词区 CPU 时间分别下降约 22%/18%。这是含诊断计数的计算开销测量，不是实际屏幕帧率；原生阶段、混排文字与默认/最大设置的阅读锚点另做回归。
