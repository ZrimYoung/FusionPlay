# FusionPlay Mac · 测试版

macOS 14+ / Apple Silicon。原生 SwiftUI 菜单栏界面，通过 UniFFI 调用共享 Rust MiPlay SDK，音频直接交给 macOS 输出。

## 使用

在独立项目根目录双击 `启动.command` 或打开应用，程序会读取已保存设置并自动启动接收服务。可随时点击“停止接收”；关闭或重新打开播放窗口不会重启已手动停止的服务，完整退出并重新打开应用则自动启动。不会添加登录启动项。手机连接同一局域网，关闭影响本地通信的代理，在妙播中选择 `FusionPlay-Mac`。全屋播放由手机组织，将 Mac 与音箱一起加入即可。

首次出现局域网权限提示时允许访问。在“设置”中可以选择网卡和输出设备；默认自动选择局域网、跟随系统音频输出。修改设置后需要重新连接，手机可能需要重新选择设备。

关闭设置窗口不会停止接收。“停止接收”释放接收器；“退出”或 `停止.command` 关闭应用。不安装登录启动项，不修改全局 Python、Rust 或 shell 配置。

打开应用时显示独立播放窗口；点击程序坞图标可再次打开。菜单栏面板的“正在播放”也可打开该窗口，显示封面、歌名、歌手、音量与手机提供的进度。背景使用当前封面模糊铺满，无封面时显示安静渐变；播放按钮在支持的系统上使用原生玻璃效果，旧系统使用半透明材质，减少透明度设置下使用实色。播放页不显示底部状态栏或接收启停按钮；接收启停保留在菜单栏。关闭播放窗口也继续接收。菜单栏与播放窗口都提供上一曲、播放/暂停、下一曲。

实际播放后，应用通过 macOS MediaPlayer 接入控制中心/系统菜单栏的“正在播放”及键盘媒体键。系统菜单栏是否展示“正在播放”取决于系统设置；多个音乐应用同时运行时，由 macOS 决定媒体键的控制目标。停止接收、断开会话、睡眠或退出时清除本应用媒体信息。

控制操作发送给手机播放源。界面区分“指令已发送”和“手机已确认”；未确认不自动重发，以免重复切歌。全屋播放时对整组的影响由手机决定，需要实播验证。仅连接或握手不会占用系统“正在播放”。

封面支持手机提供的 HTTP/HTTPS 图片地址、`data:image/...;base64,...` 内嵌图片及无前缀 Base64 图片，最多 4 MB，使用临时内存加载，不写图片磁盘缓存。网络超时或服务端临时错误最多尝试三次；设置中的“专辑封面”区分手机未提供、正在加载和加载失败，并可手动重新加载。时长/位置缺失时不伪造进度；进度随手机上报更新，本版不支持拖动定位，也不向系统注册快进/快退。

为兼容手机提供的 HTTP 封面，本应用设置了自身的 ATS 例外；不修改系统设置。URLSession 只用于封面 GET，不携带 Cookie 或已存凭证，不接受文件路径、带用户名密码的 URL 或其他协议；HTTPS 仍执行系统证书验证。

0.3.0 起安装在 `/Applications/FusionPlay Mac.app`，运行数据位于 `~/Library/Application Support/FusionPlay`，不依赖外置盘。旧版首次迁移可运行 `python3 macos/scripts/install-local.py`，复制并校验配置、身份，拒绝覆盖已有安装。源码与构建缓存留在项目目录。

## 构建与验证

需要 Rust stable（支持 edition 2024）、Apple Command Line Tools（Swift 6 工具链）和网络访问。Swift 源码以 Swift 5 语言模式编译，以兼容 UniFFI 0.29.4；UI 使用 macOS 14 API。

```sh
bash macos/scripts/build.sh
bash macos/scripts/install-entries.sh
bash macos/scripts/test-bridge.sh
bash macos/scripts/test-artwork.sh
# 在有可用局域网且未运行本应用时：
bash macos/scripts/test-bridge.sh --network
# 原生 MediaPlayer 发布/暂停/清理检查（短暂使用测试曲目，结束后清除）：
bash macos/scripts/test-bridge.sh --network --system-media
python3 -m unittest discover -s macos/Tests
```

`env.sh` 优先使用相邻 Android 项目已有的工具链，依赖缓存和构建产物均写入本项目。其他机器使用 PATH 中的 Rust；可通过 `FUSIONPLAY_PROJECT_ROOT` 指定独立产物根目录。应用使用本地 ad-hoc 签名，没有 Developer ID 公证。

Rust 测试：在 bash 中加载 `macos/scripts/env.sh`，然后分别对 `src/FusionPlay.MiPlaySdk/Cargo.toml` 和 `src/FusionPlay.Host/Cargo.toml` 执行 `cargo test --locked --manifest-path …`。部分测试会绑定本地套接字，需要允许本地网络操作。

## 架构与分支兼容

- `src/FusionPlay.MiPlaySdk`：唯一共享协议核心。Mac 音频回调使用固定容量 SPSC 缓冲，保留每帧时间戳；小偏差平滑调速，严重失步先淡出再重新同步。
- `src/FusionPlay.Host`：新增类型化宿主契约与 UniFFI 适配。Swift 接收状态快照，不解析 SDK 内部 JSON。事件线程处理日志和 UI 订阅，音频线程不调用 Swift。
- `macos`：原生 UI、打包及清理入口。Android Flutter/Kotlin/JNI 保留原实现。

平台修复以 `target_os = "macos"` 隔离。共享 Lyra 生命周期修复单独提交，供 Android 分支独立合入。基线与分支见 `BASELINE.md`。不复制核心、不重命名现有 Android 工程、不修改其包名或校准值。

## 诊断及实播验收

日志在项目 `logs/receiver.jsonl`，单文件约 5 MB 轮换一次，只保留当前与上一份。记录缓冲量、输出延迟、调度误差、欠载、丢帧和重新同步计数；不保存认证材料、原始包、封面或曲目信息。设备身份和设置在 `data`，目录权限 700，文件 600。

封面诊断另存 `logs/artwork.jsonl`，约 50 KB 轮换，只记录来源格式（HTTP/HTTPS/内嵌/无前缀编码/手机地址/缺失）、结果代码和尝试次数，不记录 URL、查询参数、歌曲名或图片内容。

先以 Mac 内置扬声器验证：发现、连接、播放/暂停、重连、加入/退出全屋，然后连续播放至少 30 分钟。观察是否有毛刺、断音或随时间扩大的偏差。启动对齐产生的丢帧与持续播放期间的异常需要分别判断。

20 ms 是工程目标，必须用同一录音中的瞬态信号测量；菜单栏“调度误差”不等于声学同步偏差。只取得听感反馈时标记“主观通过，客观偏差未测”。蓝牙音频设备不属于首版同步验收对象。

网络或输出设备变化会触发受控重连；失败最多自动重试三次。睡眠时停止，唤醒后恢复用户此前请求的接收状态。手机可能需要重新选择设备。实际睡眠、网络切换及输出切换仍需逐项实测记录。

实播中断或未完成不能宣称毛刺已修复。详见 `VALIDATION.md`。

系统媒体验收：手机投送后，检查控制中心曲目和封面，再分别使用键盘、系统卡片、菜单栏、独立窗口操作播放/暂停和切歌；确认手机实际变化、暂停后没有误显示播放、断开后卡片消失。与其他音乐应用切换时检查媒体键归属。原生接口测试通过不等于以上实播已通过。

## 清理

设置中的“打开数据与卸载目录”可找到 `卸载 FusionPlay.command`。查看清单并输入 `DELETE` 后，会退出应用并删除内置盘应用、本应用运行数据、偏好、窗口状态和专用缓存。外置盘源码、构建产物、缓存以及迁移前备份保留；系统隐私授权记录不承诺清除。

迁移前外置盘 `data` 和 `logs` 保留为备份，不再作为当前运行目录。原 `macos/scripts/cleanup.py` 仍是外置盘开发产物清理工具，与安装版卸载分开。

项目继承 AGPL-3.0-only 许可证；分发应用时应同时提供对应源码与许可证。

应用图标位于 `macos/Resources/AppIcon.png`，采用浅底蓝色双环与轻微玻璃质感；提示词和生成方式见同目录 `AppIcon.prompt.json`。构建自动生成多分辨率 ICNS，不需要额外图像工具依赖。

菜单栏使用单色双环标志，面板保留名称/状态、当前曲目、播放控制和音量。底部从左到右为接收启停、正在播放、设置、日志、退出；每个图标有悬停说明和无障碍名称。接收启停与退出是独立操作。

运行时显式设置 Dock 图标，使用带透明外边距的圆角图块，图块内部保持不透明。图标回归检查：`bash macos/scripts/test-brand.sh`。

控制连接的局部错误会记录到诊断日志而不会重启整个接收器；日志使用 `scope`、`recovery` 和固定 `reason_hint` 分类，不保存原始错误内容。真正的音频输出或监听故障仍走接收器恢复流程。

菜单和播放窗口共享音量拖动状态，拖动/提交期间忽略旧音量回报，命令完成并收到对应回报后恢复跟随手机。回报丢失时最多等待两秒，避免永久锁住滑条。回归测试：`bash macos/scripts/test-volume.sh`。

### 0.2.6 设备发现与恢复

Mac 安装保存自己的控制端口，避免默认复用电视常见的 8899。首次升级保留设备身份并迁移配置；端口被占用时保存实际分配的替代端口。此措施降低旧地址误连其他设备的风险，不能清除手机上已有的错误记录，升级后手机可能需要重新选择设备。

### 可缩放播放窗口

拖动窗口边缘可缩放，最小内容尺寸为 260 × 260。宽度不足 600 或高度不足 360 时采用封面迷你模式，保持 1:1 缩放，鼠标移入显示曲目信息和上一曲、播放/暂停、下一曲，移出后隐藏。VoiceOver 启用时保留控件；普通模式仅悬浮显示，移出隐藏。放大后自动恢复左右布局；无封面显示音符占位。窗口背景支持拖动，关闭窗口继续接收。

迷你悬浮层右侧的图钉可切换窗口置顶；再次点击取消。置顶状态属于当前播放窗口，不写入设备身份。模糊背景根据控件实际高度向上增加 24 点过渡空间，随歌名换行和窗口大小变化。
